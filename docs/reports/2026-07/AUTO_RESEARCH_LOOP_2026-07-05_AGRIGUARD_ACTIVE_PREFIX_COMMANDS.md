## A/B Contract

- Baseline: the initial operator packet generated by `launch_compose.py`
  embedded a `guarded_launch` rerun command using default guarded output paths,
  even when `run_guarded_launch.py` was invoked with a custom `--output-prefix`.
- Variant: thread active guarded output metadata from `run_guarded_launch.py` to
  `launch_compose.py`, and from there into `render_launch_operator_packet.py`.
- Primary KPI: real readiness and consumer artifacts show the `guarded_launch`
  next command using the active prefix and matching status/handoff paths.
- Guardrails: default direct `launch_compose.py` behavior remains unchanged,
  handoff validation still passes, the Firebase blocker remains fail-closed,
  and AgriGuard smoke/browser checks remain green.
- Decision rule: adopt only if focused tests, real guarded-wrapper proof,
  broader launch-readiness tests, workspace smoke, and browser smoke all pass.

## Baseline Evidence

Real guarded-wrapper proofs from earlier cycles showed
`readiness_next_commands[guarded_launch]` using:

- `--output-prefix agriguard-guarded-launch`
- `var/agriguard-guarded-launch-status.json`

even when the current wrapper prefix was different. That made the recovery
command copy-paste-safe but not bundle-local.

## Variant Evidence

- `launch_compose.py` now accepts guarded output metadata flags:
  `--guarded-output-dir`, `--guarded-output-prefix`, `--guarded-status-json`,
  `--guarded-handoff-json`, `--guarded-handoff-markdown`,
  `--guarded-handoff-validation-json`, `--guarded-handoff-consumer-json`, and
  `--guarded-ready-gate-json`.
- `launch_compose.py` forwards those flags to `render_launch_operator_packet.py`
  when rendering the initial operator packet.
- `run_guarded_launch.py` now builds the delegated `launch_compose.py` command
  after resolving effective status and handoff paths, then passes the active
  guarded output metadata into that delegated command.
- Dry-run tests cover default behavior, active guarded metadata, custom handoff
  paths, and custom status JSON.
