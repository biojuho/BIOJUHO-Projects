## 목표

직접 수집이 막힌 클리앙·82cook·딴지일보의 인기글을 jamnanda 경유로 화면에 올린다.
IssueLink와 같은 어그리게이터 자리를 쓰고, 직접 수집 소스는 건드리지 않는다.

## 언제 시작하는가

두 가지가 정리된 뒤다.

1. **`handoffs/0005`가 DONE.** 판정 재현율이 2/20인 상태에서 소스만 늘리면 걸러질 것만
   늘고 화면은 그대로다. 2026-08-07 실측에서 jamnanda 29건은 **전량 커널 사는 축 0건**이었다.
   판정을 먼저 고치고 소스를 붙이는 순서여야 의미가 있다.
2. **`fast_viral_collector.py`가 비었을 때.** 이 작업은 그 파일의 어그리게이터 구간을
   건드려야 하는데, 0002(Codex)와 0004가 같은 파일에 있다. 둘이 병합되기 전에 손대면
   삼중 충돌이다.

## 배경

2026-08-07에 사용자가 지목한 어그리게이터 6곳(moamoa·aagag·issuelink·jamnanda·
todaybeststory·playboard)을 robots 확인 후 실제로 수집해 봤다. 결과는 `STATE.md`의
"외부 어그리게이터 조사" 표에 있고, **새 정보를 주는 곳은 jamnanda 하나였다.**

jamnanda가 수집하는 커뮤니티는 보배드림·오늘의유머·웃긴대학·뽐뿌·루리웹·이토랜드로
**우리가 이미 직접 읽는 곳과 대부분 겹친다.** 겹치지 않는 건 셋이다:

| 커뮤니티 | 우리 상태 | jamnanda 실측(2026-08-07 새벽) |
|----------|-----------|-------------------------------|
| 클리앙 | robots.txt조차 403, 제외 | 5건 |
| 82cook | IP 443 거부로 직접 수집 제외, IssueLink 경유만 | 9건 |
| 딴지일보 | 미착수 | 15건 (전량 정치) |

**기대치를 낮게 잡는다.** 딴지일보는 사실상 정치 전문이라 제외 필터가 대부분 걷어낸다.
에펨코리아·MLB파크·인벤은 jamnanda 메뉴에 있지만 "등록된 게시물이 없습니다" 상태다.
이 작업으로 늘어나는 실질 소재는 **하루 몇 건 수준**일 수 있다. 그래도 클리앙·82cook은
지금 완전히 비어 있는 창구라 0에서 몇 건은 의미가 있다는 판단으로 발행한다.

## 반드시 알고 시작할 것 — jamnanda는 메트릭을 주지 않는다

실측으로 확인했다. 한 항목(`div.card.mb-3`)이 담는 것은 이게 전부다:

```
제목 · 원문 URL · 커뮤니티명(82쿡) · 경과시간(44분전) · 순위 · 찜 버튼
```

**조회수·댓글수·추천수가 없다.** 그래서:

- `DIRECT_COMMUNITY_SOURCES`에 넣으면 **전량 탈락한다.** `has_min_traction`이 조회 300 /
  댓글 5 / 추천 10 중 하나를 요구하는데 셋 다 0이기 때문이다. 직접 소스로 붙이려 하지 말 것.
- 갈 곳은 **IssueLink와 같은 어그리게이터 경로**다. 거기는 클러스터 관측
  (`_community_x_exposure_assessment`)으로 점수를 매기고 `aggregator_quota`로 자리를 받는다.
  메트릭이 없어도 동작하도록 이미 설계돼 있다.

한 가지는 IssueLink보다 낫다. **jamnanda는 원문 URL을 그대로 준다**(`www.clien.net/...`,
`www.82cook.com/...`). IssueLink처럼 리다이렉트를 풀 필요가 없으므로
`_resolve_community_origins` 요청을 아낄 수 있다. `link_kind`는 `publisher_original`이다.

## 획득 방식 (조사 완료분)

- robots: `User-agent: * / Allow: /` — 제한 없음. Cloudflare·로그인 없음.
- 목록 URL: `https://jamnanda.com/commbest/list/?c_m=<key>`
  (`clien` · `82cook` · `ddanzi` · 그 외 `bobaedream`/`ppomppu`/`ruliweb`/`todayhumor`/
  `humoruniv`/`etoland`는 **우리가 직접 읽으므로 넣지 않는다** — 중복 수집이다)
- 파싱 지점: `<div class="card mb-3">` 단위. 그 안에서
  - 제목·원문 URL → `a.contents_link`
  - 커뮤니티명 → `span.text-gray-900`
  - 경과시간 → `span.text-muted` (예: `44분전`)
- 시간 필터(`slt_time`)는 **POST 폼 전용**이라 GET 쿼리로는 안 먹는다. 확인했다.
  기본 목록만 쓰거나, POST가 필요하면 세션·CSRF까지 봐야 하므로 범위 밖으로 둔다.

## 범위

- **건드릴 것:**
  - 새 파서 모듈 또는 `direct_community_sources.py`의 파서 함수(파싱 로직만)
  - `fast_viral_collector.py`의 **어그리게이터 구간만** (IssueLink 처리 옆)
  - `_COMMUNITY_LABELS`에 라벨 추가(클리앙·82cook은 이미 있으니 딴지만)
  - 해당 테스트
- **건드리지 말 것:**
  - `DIRECT_COMMUNITY_SOURCES` — 위에 쓴 이유로 여기가 아니다
  - `has_min_traction`·`passes_spread_gate`·`_direct_signal_score` — 메트릭 없는 소스를
    받으려고 직접 수집의 기준을 낮추면 안 된다. 그건 다른 소스들을 망가뜨린다.
  - `kernel_screen.py` — 0005 영역
  - 제외 필터(`content_filters.py`) — 딴지 정치글이 걸리는 건 **정상 동작**이다.
    통과시키려고 필터를 풀지 말 것.

## 단계

1. 파서를 먼저 만들고 테스트로 고정한다(저장된 HTML 픽스처 사용, 네트워크 없이).
2. 어그리게이터 경로에 붙인다. IssueLink 항목과 같은 형태(`signal_source`, `link_kind`,
   클러스터 관측)로 만들어 기존 로직이 그대로 먹게 한다.
3. 중복 제거를 확인한다. jamnanda가 보배·뽐뿌·루리웹도 싣기 때문에, 우리 직접 수집분과
   같은 글이 두 번 올라오면 안 된다(`_snapshot_item_key` 기준).
4. `aggregator_quota` 자리를 IssueLink와 어떻게 나눌지 정한다. **자리를 늘리지 말고
   기존 몫 안에서 나눈다** — 어그리게이터가 화면을 더 먹으면 직접 수집이 밀린다.
5. 실수집으로 확인하고 숫자를 반환 섹션에 적는다.

## 금지사항

- 메트릭이 없다고 직접 수집의 트랙션 기준을 낮추지 않는다(위 참고).
- 딴지 정치글을 통과시키려고 제외 필터를 손대지 않는다.
- jamnanda가 이미 우리가 읽는 커뮤니티를 중복 수집하게 하지 않는다.
- 되돌릴 수 없는 외부 행위는 사용자 승인 없이 금지. **커밋은 하되 push 금지.**

  걸린다면, 붙이지 말고 그 사실을 반환 섹션에 적어 되돌린다. **값이 없으면 안 붙이는 게 맞다.**
