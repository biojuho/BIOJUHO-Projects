# 핸드오프 0001 — 대시보드 수집 신선도 상시 표시

- **기획자:** Claude
- **추천 실행자:** Codex
- **실행자:** Claude (사용자가 이어서 진행 요청)
- **작성일:** 2026-08-06

## 목표

각 수집 레인이 **마지막으로 언제 갱신됐는지**를 대시보드 화면에 상시 표시하고, 일정 시간 이상
멈추면 눈에 띄게 경고한다.

## 배경

2026-08-06 점검에서 데이터가 11:20 이후 갱신되지 않은 채 세 시간 넘게 방치된 것이 발견됐다.
서버는 살아 있었고(8010 HTTP 200) 테스트도 801개 전부 통과했지만, 수집이 멈춘 사실 자체를
알아챌 방법이 없었다. 현재 마지막 실행 시각은 `dashboard_html.py:670`에서 파이프라인 pill의
`title` 속성(마우스를 올려야 뜨는 툴팁)에만 들어간다.

수집이 멈추는 것은 고장이 아니라 구조다 — 자동 갱신이 서버가 아니라 브라우저 `setInterval`
(X 레이더·급속 바이럴 2분, 라이브 레퍼런스 10분)에서 돌기 때문에 탭을 닫으면 멈춘다.
상시화(별건)를 하든 안 하든, **멈춘 걸 즉시 알 수 있어야** 한다.

## 범위

- **건드릴 것:** `automation/getdaytrends/dashboard_html.py`(배지 렌더·경고 임계), 필요하면
  각 레인 API 응답에 `last_collected_at`을 싣는 `dashboard_routes_*.py`, 그리고 대응 테스트.
- **건드리지 말 것:** 수집 로직·점수 계산·필터 규칙, 데이터 스키마의 기존 필드, 외부 API 호출 빈도.
  자동 게시·문안 생성 기능은 이 프로젝트에 없다 — 추가하지 않는다.

## 단계

1. 각 레인(X 레이더 · 급속 바이럴 · 라이브 레퍼런스 · 커뮤니티 원문)의 마지막 수집 시각을
   API 응답에서 확정한다. 이미 있으면 그대로 쓰고, 없으면 관측 파일의 최신 타임스탬프에서 얻는다.
2. 레인 헤더에 `N분 전 갱신` 배지를 상시 표시한다. 툴팁이 아니라 본문에 보여야 한다.
3. 임계를 넘으면 색과 문구로 경고한다 — 기본값 제안: 2분 주기 레인은 10분, 10분 주기 레인은 30분.
   경고 문구에 원인 힌트를 넣는다("브라우저 탭이 닫혀 있으면 수집이 멈춥니다").
4. 시각은 화면 표기 기준을 하나로 맞춘다. 관측 파일은 UTC로 저장되는데(예: `2026-08-06T02:20`),
   사용자가 보는 시각은 KST(11:20)여야 한다. 여기서 어긋나면 신선도 판단이 통째로 틀어진다.
5. 테스트를 추가한다: 신선할 때 배지 정상, 임계 초과 시 경고, 타임스탬프 없음일 때 `-` 표시.

## 수용 게이트

- `.venv/bin/python -m pytest automation/getdaytrends/tests -q` → 기존 801개 유지 + 신규 통과.
- 대시보드를 띄워 배지가 실제로 보이고, 수집을 멈춘 뒤 임계를 넘기면 경고로 바뀌는 것을 눈으로 확인.
- KST 표기가 관측 파일의 UTC와 9시간 차이로 정확히 대응하는지 한 건 이상 대조.

## 금지사항

- 되돌릴 수 없는 외부 행위(배포·게시·삭제·결제·외부 전송)는 사용자 명시 승인 없이 금지.
- 비밀키·토큰 노출 금지. 수집 빈도를 임의로 올리지 않는다(이 핸드오프는 표시 문제만 다룬다).

## 반환

**결과**

신선도 판정을 서버로 옮겼다. `freshness.py`가 마지막 갱신 시각을 나이·등급(fresh/warn/stale/unknown)·
한국어 문구로 환산하고, `/api/x-radar`·`/api/fast-viral` GET 응답에 `freshness` 필드로 실린다.
화면은 등급만 받아 쓴다 — 임계를 프론트와 서버 두 곳에 두면 판단이 갈리기 때문이다.
임계는 브라우저 갱신 주기의 3배(경고)와 7~8배(멈춤)로 잡았다: 2분 레인은 6분/15분.

화면 변화는 셋이다. `갱신 2026. 8. 6. 오전 11:20:37` 같은 절대 시각이 `갱신 3시간 전 (11:20)`으로
바뀌었고, 등급에 따라 색이 붙으며, stale이면 "수집 멈춤 — 대시보드 탭을 닫으면 자동 갱신이 서지
않습니다" 힌트가 뜬다. 무엇보다 `live-dot`이 등급에 연동됐다 — 지금까지는 수집이 세 시간 멈춰도
빨간 점이 계속 뛰어서 살아 있는 것처럼 보였다.

**기획 단계의 오진 정정**

이 핸드오프는 "마지막 시각이 툴팁에만 있다"와 "UTC→KST 변환 함정"을 전제로 썼는데, 둘 다 실제와
달랐다. 툴팁뿐인 건 파이프라인 pill 한 곳이고 각 레인은 이미 본문에 시각을 표시하고 있었다.
타임스탬프도 `2026-08-06T02:20:37.275112+00:00`처럼 오프셋이 붙어 있어 `new Date()`가 알아서
로컬로 변환한다 — 변환 버그는 없었다. 진짜 갭은 **절대 시각만 있고 경과·경고가 없다는 것**과
**라이브 표시가 상태와 무관하게 켜져 있다는 것**이었다. 목표(멈춘 걸 즉시 알 수 있게)는 그대로다.

**실행한 명령**

  (기존 801 유지 + 신규 26). 스킵 7건은 Kiwipiepy·Scrapling 미설치로 기존과 동일.

**남은 것**

- **라이브 레퍼런스 레인 제외.** 이 레인은 GET 스냅샷이 아니라 `POST /live/refresh` 응답에서만
  `refreshed_at`을 읽는 구조여서 같은 방식이 바로 맞지 않는다. `live/status` 응답에 시각을 싣는
  선행 작업이 필요하다.
- **실행 중인 서버는 구버전.** 8010에 떠 있는 프로세스는 `--reload` 없이 10:07에 기동돼 이 변경을
  아직 반영하지 않았다. 재시작해야 화면에 보인다.
- 임계값(6분/15분)은 첫 제안이다. 실제로 며칠 써 보고 경고가 너무 잦거나 무디면 조정한다.
